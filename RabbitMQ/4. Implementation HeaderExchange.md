# RabbitMQ Headers Exchange Implementation in .NET Microservices

## 1. What is Headers Exchange?

RabbitMQ supports different exchange types:

1. Direct Exchange
2. Fanout Exchange
3. Topic Exchange
4. Headers Exchange

In this guide, we will implement **Headers Exchange** in our existing e-commerce microservices application.

A Headers Exchange routes messages based on message headers instead of routing keys.

Headers are additional metadata attached to a message in key-value format.

For example:

```text
eventType = product.delete
service   = product-service
priority  = 2
```

The Publisher attaches these headers to a message.

The Headers Exchange checks the message headers against the binding arguments configured by the Consumer.

If the headers match, RabbitMQ routes the message to the corresponding queue.

### Direct Exchange vs Headers Exchange

| Direct Exchange | Headers Exchange |
|---|---|
| Routes using routing keys | Routes using message headers |
| Matches routing keys exactly | Matches header keys and values |
| Example: `product.delete` | Example: `eventType=product.delete` |
| Simple event routing | Routing based on multiple metadata values |

## 2. Understand Headers Exchange Architecture

In our e-commerce application, we have:

- Product Service
- Order Service
- RabbitMQ

We will use Direct Exchange for product updates and Headers Exchange for product deletions.

### Product Update — Direct Exchange

```text
Product Service
      |
      | Routing Key: product.update
      v
Direct Exchange
(exchange.product)
      |
      v
Update Queue
      |
      v
Order Service
```

### Product Delete — Headers Exchange

```text
Product Service
      |
      | Message Headers:
      | eventType = product.delete
      | service = product-service
      |
      v
Headers Exchange
(exchange.product.headers)
      |
      | Matches headers
      v
Delete Queue
      |
      v
Order Service
```

**Important:** The publisher sends the message to an exchange, not directly to a queue.

## 3. How does Headers Exchange work?

Let's understand using our Product Delete scenario.

Suppose Product Service deletes a product.

Instead of sending `product.delete` as a routing key, we attach it as a message header.

### Publisher sends:

**Message Headers:**

```text
eventType = product.delete
service   = product-service
```

**Message Body:**

```json
{
  "ProductID": "663e4214-e12a-11f1-b175-8ce9eeba9a59"
}
```

The Headers Exchange checks these headers against the binding arguments of the queues.

For example, our Order Service binds its delete queue with:

```text
eventType = product.delete
service   = product-service
```

Both values match, so RabbitMQ routes the message to the delete queue.

### What is x-match?

`x-match` is a special binding argument used by Headers Exchange.

It supports two values:

**1. x-match = all**

All specified header conditions must match.

Example:

```text
x-match    = all
eventType  = product.delete
service    = product-service
```

Both conditions must match.

**2. x-match = any**

At least one specified header condition must match.

Example:

```text
x-match    = any
eventType  = product.delete
priority   = 2
```

Either condition can match.

## 7. Implement PublishWithHeaders()

Inside our existing `RabbitMQPublisher.cs`, add the following method.

```csharp
public async Task PublishWithHeaders<T>(T message, string eventType)
{
    string exchangeName = "exchange.product.headers";

    // Declare Headers Exchange
    await channel!.ExchangeDeclareAsync(
        exchange: exchangeName,
        type: ExchangeType.Headers,
        durable: true,
        autoDelete: false
    );

    // Create message headers
    var properties = new BasicProperties
    {
        Headers = new Dictionary<string, object?>
        {
            { "eventType", eventType },
            { "service", "product-service" }
        }
    };

    // Convert message into JSON
    string messageString = JsonSerializer.Serialize(message);

    // Convert JSON into byte array
    byte[] messageBody = Encoding.UTF8.GetBytes(messageString);

    // Publish message to Headers Exchange
    await channel.BasicPublishAsync(
        exchange: exchangeName,
        routingKey: string.Empty,
        mandatory: false,
        basicProperties: properties,
        body: messageBody
    );
}
```

Add the following namespace:

```csharp
using System.Collections.Generic;
```

### Understand the important parts

**1. Declare Headers Exchange**

```csharp
await channel!.ExchangeDeclareAsync(
    exchange: "exchange.product.headers",
    type: ExchangeType.Headers,
    durable: true,
    autoDelete: false
);
```

We create an exchange named `exchange.product.headers` with type Headers.

We use a different exchange name because our existing `exchange.product` is already a Direct Exchange.

RabbitMQ does not allow changing an existing exchange's type simply by declaring it again with another type.

**2. Create message headers**

```csharp
var properties = new BasicProperties
{
    Headers = new Dictionary<string, object?>
    {
        { "eventType", eventType },
        { "service", "product-service" }
    }
};
```

This is the most important part.

We attach additional metadata to our message.

For example:

```text
eventType = product.delete
service   = product-service
```

Here:

- `eventType` is the header key.
- `product.delete` is the header value.
- `service` is another header key.
- `product-service` is its value.

**3. Publish the message**

```csharp
await channel.BasicPublishAsync(
    exchange: exchangeName,
    routingKey: string.Empty,
    mandatory: false,
    basicProperties: properties,
    body: messageBody
);
```

Notice that the routing key is empty.

Why?

Because Headers Exchange does not use routing keys for routing. It uses the message headers.

The `basicProperties` parameter carries our headers along with the message body.

## 8. How to publish a Product Delete event?

Inside our existing `ProductService.cs`, we have:

```csharp
public async Task<bool> DeleteProductAsync(Guid productId)
{
    bool isDeleted =
        await _productRepository.DeleteProductAsync(productId.ToString());

    if (!isDeleted)
    {
        return false;
    }

    await _cache.RemoveAsync("all_products");

    // Publish delete event using Headers Exchange
    await _rabbitMQPublisher.PublishWithHeaders(
        new { ProductID = productId },
        "product.delete"
    );

    return true;
}
```

### What happens here?

1. Product Service deletes the product from the database.
2. If deletion succeeds, it invalidates the Redis cache.
3. It calls `PublishWithHeaders()`.
4. The publisher attaches `eventType=product.delete` and `service=product-service` to the message.
5. It publishes the message to `exchange.product.headers`.

The resulting message contains:

**Headers:**

```text
eventType = product.delete
service   = product-service
```

**Body:**

```json
{
  "ProductID": "663e4214-e12a-11f1-b175-8ce9eeba9a59"
}
```

## 11. Implement ConsumeProductDeleteWithHeaders()

Inside our existing `RabbitMQConsumer.cs`, add:

```csharp
public async Task ConsumeProductDeleteWithHeaders()
{
    // Queue Declaration
    string queueName = "order.product.delete.headers.queue";

    await _channel.QueueDeclareAsync(
        queue: queueName,
        durable: true,
        autoDelete: false,
        exclusive: false
    );

    // Exchange Declaration
    string exchangeName = "exchange.product.headers";

    await _channel.ExchangeDeclareAsync(
        exchange: exchangeName,
        type: ExchangeType.Headers,
        autoDelete: false,
        durable: true
    );

    // Define binding headers
    var bindingHeaders = new Dictionary<string, object?>
    {
        { "x-match", "all" },
        { "eventType", "product.delete" },
        { "service", "product-service" }
    };

    // Bind Queue to Headers Exchange
    await _channel.QueueBindAsync(
        queue: queueName,
        exchange: exchangeName,
        routingKey: string.Empty,
        arguments: bindingHeaders
    );

    // Consumer Setup
    AsyncEventingBasicConsumer consumer =
        new AsyncEventingBasicConsumer(_channel);

    consumer.ReceivedAsync += async (model, ea) =>
    {
        Console.WriteLine("DELETE MESSAGE RECEIVED FROM RABBITMQ!");

        var body = ea.Body.ToArray();

        var message = Encoding.UTF8.GetString(body);

        var productDelete =
            JsonSerializer.Deserialize<ProductDeleteMessage>(message);

        Console.WriteLine($"Received message: {message}");

        Console.WriteLine(
            $"Product ID: {productDelete?.ProductID}"
        );

        await Task.CompletedTask;
    };

    // Start Consuming
    await _channel.BasicConsumeAsync(
        queue: queueName,
        autoAck: true,
        consumer: consumer
    );
}
```

Make sure the following namespaces are available:

```csharp
using System.Collections.Generic;
using RabbitMQ.Client;
using RabbitMQ.Client.Events;
using System.Text;
using System.Text.Json;
```

### Understand the important parts

**1. Declare the queue**

```csharp
string queueName = "order.product.delete.headers.queue";
```

This queue will receive product deletion messages.

**2. Declare the Headers Exchange**

```csharp
await _channel.ExchangeDeclareAsync(
    exchange: exchangeName,
    type: ExchangeType.Headers,
    autoDelete: false,
    durable: true
);
```

Notice that the exchange type is now `ExchangeType.Headers`.

It must match the exchange declaration on the Publisher side.

**3. Define binding headers**

```csharp
var bindingHeaders = new Dictionary<string, object?>
{
    { "x-match", "all" },
    { "eventType", "product.delete" },
    { "service", "product-service" }
};
```

Here we tell RabbitMQ which messages our queue wants to receive.

- `x-match = all`: All conditions must match.
- `eventType = product.delete`: Only product deletion events.
- `service = product-service`: Only messages carrying this service value.

**4. Bind the queue**

```csharp
await _channel.QueueBindAsync(
    queue: queueName,
    exchange: exchangeName,
    routingKey: string.Empty,
    arguments: bindingHeaders
);
```

This connects our delete queue to the Headers Exchange.

RabbitMQ will check the message headers against these binding arguments.

**5. Consume the message**

```csharp
consumer.ReceivedAsync += async (model, ea) =>
{
    var body = ea.Body.ToArray();

    var message = Encoding.UTF8.GetString(body);

    var productDelete =
        JsonSerializer.Deserialize<ProductDeleteMessage>(message);

    Console.WriteLine($"Product ID: {productDelete?.ProductID}");

    await Task.CompletedTask;
};
```

Whenever RabbitMQ delivers a matching message, `ReceivedAsync` is triggered.

We read the message body, deserialize it, and access the ProductID.

# PART C: STRING, INTEGER AND OTHER HEADER VALUES

## 13. Can we send different data types in headers?

Yes!

RabbitMQ headers support different AMQP field-table value types, including strings, integers, booleans, and other supported types.

In C#, we use `object` values in the dictionary.

Example:

```csharp
var properties = new BasicProperties
{
    Headers = new Dictionary<string, object?>
    {
        { "eventType", "product.delete" },
        { "priority", 2 },
        { "isCritical", true },
        { "source", "product-service" }
    }
};
```

Here:

| Header key | Value | Type |
|---|---|---|
| eventType | product.delete | String |
| priority | 2 | Integer |
| isCritical | true | Boolean |
| source | product-service | String |

The consumer can bind using these values:

```csharp
var bindingHeaders = new Dictionary<string, object?>
{
    { "x-match", "all" },
    { "eventType", "product.delete" },
    { "priority", 2 }
};
```

The message must match both the event type and priority.

**Important:** Header matching uses the value and its type. For example, integer `2` and string `"2"` are not equivalent.

# PART D: REAL-WORLD E-COMMERCE EXAMPLE

## 14. When should we use Headers Exchange?

Imagine our e-commerce application receives different types of events.

| Event | Header values | Consumer |
|---|---|---|
| Product Deleted | eventType=product.delete | Order Service |
| Order Created | eventType=order.created | Payment Service |
| Payment Failed | eventType=payment.failed | Notification Service |
| High Priority Order | eventType=order.created, priority=2 | Priority Queue |

Headers Exchange is useful when we need to route messages based on multiple metadata values.

For example, suppose we want a queue to receive only high-priority order events.

The publisher sends:

```text
eventType = order.created
priority = 2
```

The queue binding expects:

```text
x-match = all
eventType = order.created
priority = 2
```

Both values must match.

This allows us to route messages based on multiple conditions instead of only one routing key.

### Should we always use Headers Exchange?

No.

For simple event routing, Direct Exchange is easier.

For example:

- `product.update`
- `product.delete`
- `order.created`

Direct Exchange is perfectly suitable.

Headers Exchange is useful when routing decisions depend on multiple metadata attributes.

# PART F: INTERVIEW PREPARATION

## 16. Explain Headers Exchange in an interview

**Interviewer: What is Headers Exchange in RabbitMQ?**

Answer:

"Headers Exchange is an exchange type in RabbitMQ that routes messages based on message headers instead of routing keys.

The publisher attaches metadata to a message in key-value format. When binding a queue to a Headers Exchange, we specify the expected headers.

RabbitMQ compares the message headers with the queue's binding arguments and routes the message if the conditions match.

We can use x-match=all when all headers must match or x-match=any when at least one header must match."

### Common interview questions

**Q1. What is the difference between Direct Exchange and Headers Exchange?**

Direct Exchange routes messages using exact routing-key matching, whereas Headers Exchange routes messages based on message header values.

**Q2. Who provides headers?**

The Publisher attaches headers to the message using message properties.

**Q3. What is x-match?**

It is a special binding argument that determines how RabbitMQ matches headers.

- `all`: All specified headers must match.
- `any`: At least one specified header must match.

**Q4. Can we send multiple headers?**

Yes. Headers are key-value pairs, so we can attach multiple metadata values to a message.
