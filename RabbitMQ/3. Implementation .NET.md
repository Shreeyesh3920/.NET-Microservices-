# RabbitMQ Direct Exchange Implementation in .NET Microservices

## 1. What is RabbitMQ?

RabbitMQ is a message broker that allows different applications or microservices to communicate with each other asynchronously.

For example, in our e-commerce application, we have:

- Product Service
- Order Service
- User Service

Suppose a product is updated in Product Service. We want Order Service to know about that update.

Instead of Product Service directly calling Order Service through an HTTP API, we can publish a message to RabbitMQ.

RabbitMQ receives the message and delivers it to the appropriate queue, where Order Service consumes it.

### Why use RabbitMQ?

1. **Loose coupling:** Product Service doesn't need to know how Order Service processes the message.
2. **Asynchronous communication:** Product Service doesn't have to wait for Order Service to process the event.
3. **Reliability:** Messages can remain in durable queues while consumers are unavailable, subject to the message and broker durability configuration.
4. **Scalability:** Multiple consumers can process messages independently.

---

## 2. Understand the RabbitMQ architecture

Before implementing RabbitMQ, understand these four important components.

### 1. Publisher

The publisher sends messages to RabbitMQ.

In our application, Product Service is the publisher.

Example: When a product is updated, Product Service publishes a `product.update` event.

### 2. Exchange

An exchange receives messages from publishers and decides which queues should receive them.

Important: A publisher sends messages to an exchange, not directly to a queue.

### 3. Queue

A queue stores messages until they are delivered to consumers.

For example:

`order.product.update.name.queue`

### 4. Consumer

A consumer receives and processes messages from a queue.

In our application, Order Service is the consumer.

---

## 3. What is Direct Exchange?

RabbitMQ supports different exchange types:

- Direct Exchange
- Fanout Exchange
- Topic Exchange
- Headers Exchange

In this implementation, we are using **Direct Exchange**.

A Direct Exchange routes messages based on the routing key.

The routing key provided by the publisher must exactly match the routing key used when binding the queue.

For example:

| Queue | Binding routing key |
|---|---|
| Update Queue | `product.update` |
| Delete Queue | `product.delete` |

If the publisher sends a message with routing key `product.update`, RabbitMQ routes it to the queue bound with `product.update`.

### Our implementation architecture

Product Service publishes a product update event.

```text
              PRODUCT SERVICE
                    |
                    | Publish message
                    | Routing Key:
                    | product.update
                    |
                    v
             exchange.product
               (Direct Exchange)
                    |
                    | Routing key matches
                    v
       order.product.update.name.queue
                    |
                    | Consume message
                    v
               ORDER SERVICE
```

# PART A: PRODUCT SERVICE (PUBLISHER)

## 6. Create the Publisher Interface

Inside Product Service, create a `RabbitMQ` folder.

Create an interface named `IRabbitMQPublisher.cs`.

```csharp
public interface IRabbitMQPublisher
{
    Task ConnectAsync();

    Task Publish<T>(string routingKey, T message);
}
```

### Why use an interface?

It allows ProductService to depend on an abstraction rather than directly depending on the RabbitMQPublisher implementation.

We can also replace or mock the implementation more easily during testing.

---

## 7. Implement RabbitMQPublisher

Create `RabbitMQPublisher.cs`.

```csharp
using Microsoft.Extensions.Configuration;
using RabbitMQ.Client;
using System.Text;
using System.Text.Json;

namespace BusinessLogicLayer.RabbitMQ
{
    public class RabbitMQPublisher : IRabbitMQPublisher, IDisposable
    {
        private readonly IConfiguration configuration;

        private IConnection? connection;
        private IChannel? channel;

        public RabbitMQPublisher(IConfiguration configuration)
        {
            this.configuration = configuration;
        }

        public async Task ConnectAsync()
        {
            IConnectionFactory connectionFactory = new ConnectionFactory()
            {
                HostName = configuration["RabbitMQConfiguration:HostName"]!,
                UserName = configuration["RabbitMQConfiguration:UserName"]!,
                Password = configuration["RabbitMQConfiguration:Password"]!,
                Port = int.Parse(configuration["RabbitMQConfiguration:Port"]!)
            };

            // Establish TCP connection
            connection = await connectionFactory.CreateConnectionAsync();

            // Create AMQP channel
            channel = await connection.CreateChannelAsync();
        }

        public async Task Publish<T>(string routingKey, T message)
        {
            // Convert message into JSON
            string messageString = JsonSerializer.Serialize(message);

            // Convert JSON into byte array
            byte[] messageBody = Encoding.UTF8.GetBytes(messageString);

            string exchangeName = "exchange.product";

            // Declare Direct Exchange
            await channel!.ExchangeDeclareAsync(
                exchange: exchangeName,
                type: ExchangeType.Direct,
                autoDelete: false,
                durable: true
            );

            // Publish message to exchange
            await channel.BasicPublishAsync(
                exchange: exchangeName,
                routingKey: routingKey,
                body: messageBody
            );
        }

        public void Dispose()
        {
            channel?.Dispose();
            connection?.Dispose();
        }
    }
}
```

### Understand the important parts

**1. CreateConnectionAsync()**

```csharp
connection = await connectionFactory.CreateConnectionAsync();
```

Establishes a connection between our application and the RabbitMQ server.

**2. CreateChannelAsync()**

```csharp
channel = await connection.CreateChannelAsync();
```

Creates an AMQP channel over the connection.

We use this channel to declare exchanges and publish messages.

**3. ExchangeDeclareAsync()**

```csharp
await channel!.ExchangeDeclareAsync(
    exchange: "exchange.product",
    type: ExchangeType.Direct,
    autoDelete: false,
    durable: true
);
```

Creates a Direct Exchange named `exchange.product` if it doesn't already exist.

- `exchange`: Exchange name.
- `type`: Direct Exchange.
- `durable`: Exchange survives a RabbitMQ restart.
- `autoDelete`: Exchange is not automatically deleted when its last queue is unbound.

**4. BasicPublishAsync()**

```csharp
await channel.BasicPublishAsync(
    exchange: exchangeName,
    routingKey: routingKey,
    body: messageBody
);
```

Publishes the message to the exchange.

The exchange uses the routing key to determine which queue should receive the message.

## 9. Publish a Product Update Event

Now let's implement the actual business scenario.

Inside our ProductService, after successfully updating a product in the database, we publish an event.

```csharp
public async Task<bool> UpdateProductAsync(
    ProductUpdateRequest productUpdateRequest)
{
    if (productUpdateRequest == null)
    {
        throw new ArgumentNullException(nameof(productUpdateRequest));
    }

    // Map DTO to Entity
    var productEntity = _mapper.Map<Product>(productUpdateRequest);

    // Update product in database
    bool isUpdated =
        await _productRepository.UpdateProductAsync(productEntity);

    if (isUpdated)
    {
        // Invalidate Redis cache
        await _cache.RemoveAsync("all_products");

        // Publish event to RabbitMQ
        await _rabbitMQPublisher.Publish(
            "product.update",
            new
            {
                ProductID = productEntity.ProductID,
                ProductName = productEntity.ProductName
            }
        );
    }

    return isUpdated;
}
```

### What happens here?

1. Product Service receives an update request.
2. It updates the product in the database.
3. If the update succeeds, it invalidates the Redis cache.
4. It publishes a message to RabbitMQ.
5. The routing key is `product.update`.
6. RabbitMQ routes the message to the matching queue.

### What does the published message look like?

The publisher serializes the object into JSON.

```json
{
  "ProductID": "663e4214-e12a-11f1-b175-8ce9eeba9a59",
  "ProductName": "Gaming Laptop UPDATED"
}
```

## 12. Implement RabbitMQConsumer

Create `RabbitMQConsumer.cs`.

```csharp
using Microsoft.Extensions.Configuration;
using RabbitMQ.Client;
using RabbitMQ.Client.Events;
using System.Text;
using System.Text.Json;

namespace BusinessLogicLayer.RabbitMQ
{
    public class RabbitMQConsumer : IRabbitMQConsumer, IAsyncDisposable
    {
        private readonly IConfiguration _configuration;

        private IConnection _connection;
        private IChannel _channel;

        public RabbitMQConsumer(IConfiguration configuration)
        {
            _configuration = configuration;
        }

        public async Task ConnectAsync()
        {
            var connectionFactory = new ConnectionFactory()
            {
                HostName = _configuration["RabbitMQConfiguration:HostName"]!,
                UserName = _configuration["RabbitMQConfiguration:UserName"]!,
                Password = _configuration["RabbitMQConfiguration:Password"]!,
                Port = int.Parse(_configuration["RabbitMQConfiguration:Port"]!)
            };

            // Establish connection
            _connection = await connectionFactory.CreateConnectionAsync();

            // Create channel
            _channel = await _connection.CreateChannelAsync();
        }

        public async Task Consume()
        {
            // Queue Declaration
            string queueName = "order.product.update.name.queue";

            await _channel.QueueDeclareAsync(
                queueName,
                durable: true,
                exclusive: false,
                autoDelete: false
            );

            // Exchange Declaration
            string exchangeName = "exchange.product";

            await _channel.ExchangeDeclareAsync(
                exchange: exchangeName,
                type: ExchangeType.Direct,
                autoDelete: false,
                durable: true
            );

            // Binding Queue to Exchange
            await _channel.QueueBindAsync(
                queue: queueName,
                exchange: exchangeName,
                routingKey: "product.update"
            );

            // Consumer Setup
            AsyncEventingBasicConsumer consumer =
                new AsyncEventingBasicConsumer(_channel);

            consumer.ReceivedAsync += async (model, ea) =>
            {
                Console.WriteLine("MESSAGE RECEIVED FROM RABBITMQ!");

                var body = ea.Body.ToArray();

                var message = Encoding.UTF8.GetString(body);

                var productUpdate =
                    JsonSerializer.Deserialize<ProductUpdateMessage>(message);

                Console.WriteLine($"Received message: {message}");

                Console.WriteLine(
                    $"Product ID: {productUpdate?.ProductID}, " +
                    $"Product Name: {productUpdate?.ProductName}"
                );

                await Task.CompletedTask;
            };

            // Start Consuming
            await _channel.BasicConsumeAsync(
                queue: queueName,
                autoAck: true,
                consumer: consumer
            );
        }

        public async ValueTask DisposeAsync()
        {
            if (_channel != null)
                await _channel.DisposeAsync();

            if (_connection != null)
                await _connection.DisposeAsync();
        }
    }
}
```

## 13. Understand the Consumer implementation

This is the most important part of the implementation.

### Step 1: QueueDeclareAsync()

```csharp
await _channel.QueueDeclareAsync(
    queue: queueName,
    durable: true,
    exclusive: false,
    autoDelete: false
);
```

Creates a queue named:

`order.product.update.name.queue`

A queue stores messages until they are delivered to consumers.

### Step 2: ExchangeDeclareAsync()

```csharp
await _channel.ExchangeDeclareAsync(
    exchange: "exchange.product",
    type: ExchangeType.Direct,
    autoDelete: false,
    durable: true
);
```

Declares the same Direct Exchange used by Product Service.

Both publisher and consumer must use the same exchange name and compatible exchange configuration.

### Step 3: QueueBindAsync()

```csharp
await _channel.QueueBindAsync(
    queue: queueName,
    exchange: exchangeName,
    routingKey: "product.update"
);
```

This is where we connect the queue to the exchange.

We tell RabbitMQ:

"Send messages to this queue when the routing key is `product.update`."

The routing key used here must match the routing key used by the publisher.

### Step 4: AsyncEventingBasicConsumer

```csharp
AsyncEventingBasicConsumer consumer =
    new AsyncEventingBasicConsumer(_channel);
```

Creates an asynchronous event-based consumer.

### Step 5: ReceivedAsync

```csharp
consumer.ReceivedAsync += async (model, ea) =>
{
    var body = ea.Body.ToArray();

    var message = Encoding.UTF8.GetString(body);

    var productUpdate =
        JsonSerializer.Deserialize<ProductUpdateMessage>(message);

    Console.WriteLine($"Received message: {message}");
};
```

This event executes whenever RabbitMQ delivers a message to our consumer.

Inside this event:

1. We read the message body.
2. Convert the byte array into a string.
3. Deserialize the JSON into `ProductUpdateMessage`.
4. Process the message.

### Step 6: BasicConsumeAsync()

```csharp
await _channel.BasicConsumeAsync(
    queue: queueName,
    autoAck: true,
    consumer: consumer
);
```

Registers the consumer with RabbitMQ.

Important: This does not continuously fetch messages in a loop.

RabbitMQ automatically delivers messages to the registered consumer, and its `ReceivedAsync` event is triggered when a message arrives.

### What is autoAck?

We are currently using:

```csharp
autoAck: true
```

This means RabbitMQ automatically acknowledges a message when it delivers it to the consumer.

For production applications, manual acknowledgement is generally safer:

```csharp
autoAck: false
```

After successfully processing the message:

```csharp
await _channel.BasicAckAsync(
    deliveryTag: ea.DeliveryTag,
    multiple: false
);
```

This tells RabbitMQ that the message has been successfully processed.

If processing fails and the message is not acknowledged, RabbitMQ can redeliver it, depending on the channel and consumer configuration.

## 15. Start the Consumer using IHostedService

We need to start the consumer when Order Service starts.

Instead of manually starting it from an API controller, we can use the .NET hosting lifecycle.

Create `RabbitMQProductUpdateHostedService.cs`.

```csharp
using BusinessLogicLayer.RabbitMQ;
using Microsoft.Extensions.Hosting;

public class RabbitMQProductUpdateHostedService : IHostedService
{
    private readonly IRabbitMQConsumer _rabbitMQConsumer;

    public RabbitMQProductUpdateHostedService(
        IRabbitMQConsumer rabbitMQConsumer)
    {
        _rabbitMQConsumer = rabbitMQConsumer;
    }

    public async Task StartAsync(CancellationToken cancellationToken)
    {
        await _rabbitMQConsumer.ConnectAsync();

        Console.WriteLine("RabbitMQ connected!");

        await _rabbitMQConsumer.Consume();

        Console.WriteLine("Product Update Consumer registered!");
    }

    public Task StopAsync(CancellationToken cancellationToken)
    {
        return Task.CompletedTask;
    }
}
```

### Why use IHostedService?

IHostedService allows us to execute background initialization and long-running operations as part of the application's lifecycle.

In our case:

- When Order Service starts, the RabbitMQ connection is established.
- The consumer registers itself with RabbitMQ.
- It waits for incoming messages while the API continues running.
- When the application stops, the host shuts down the registered services and disposes the singleton consumer.

Register the hosted service in Order Service `Program.cs`:

```csharp
builder.Services.AddHostedService<RabbitMQProductUpdateHostedService>();
```

# PART D: INTERVIEW PREPARATION

## 17. Explain your RabbitMQ implementation in an interview

**Interviewer: How have you implemented RabbitMQ in your microservices project?**

Answer:

"I implemented asynchronous communication between Product Service and Order Service using RabbitMQ.

For example, whenever a product is updated, Product Service first updates the database and then publishes a product update event to RabbitMQ.

I created a Direct Exchange named `exchange.product` and used `product.update` as the routing key.

On the Order Service side, I declared a queue named `order.product.update.name.queue` and bound it to the same exchange using the same routing key.

I implemented an asynchronous consumer using `AsyncEventingBasicConsumer`. Whenever RabbitMQ delivers a message, the ReceivedAsync event is triggered. I deserialize the JSON message into a strongly typed C# DTO and process it.

I also used IHostedService to register the consumer automatically when Order Service starts."

### Common interview questions

**Q1. Why do we use an exchange?**

An exchange receives messages from publishers and routes them to the appropriate queues based on its exchange type and routing rules.

**Q2. Does the publisher send messages directly to a queue?**

No. The publisher sends messages to an exchange. The exchange routes messages to queues.

**Q3. What is a routing key?**

A routing key is a string used by an exchange to determine which queue should receive a message.

**Q4. Why did you use Direct Exchange?**

Because our requirement was simple routing based on exact event names, such as `product.update` and `product.delete`.

**Q5. What is Queue Binding?**

Binding connects a queue to an exchange and defines the routing criteria for messages.

**Q6. What is the difference between Connection and Channel?**

A connection represents the TCP connection between the application and RabbitMQ.

A channel is a lightweight AMQP communication session created over that connection. We use channels to publish and consume messages.

**Q7. What happens if Order Service is unavailable?**

If the queue is durable and the message is persistent, RabbitMQ can retain the message while the consumer is unavailable, assuming the broker has not lost its data. The publisher must also handle successful delivery or failures appropriately.

**Q8. Why use IHostedService?**

It allows the RabbitMQ consumer to start automatically with the application instead of requiring a manual API call to start consuming messages.

**Q9. What is the difference between autoAck true and false?**

- `true`: RabbitMQ automatically acknowledges messages upon delivery.
- `false`: The consumer must explicitly acknowledge messages after successful processing.

**Q10. Can one publisher publish different types of events?**

Yes. I implemented a generic `Publish<T>()` method. It accepts different message types and routing keys, so we can reuse the same publisher for product updates, product deletions, and other events.

# PART E: IMPORTANT PRODUCTION CONSIDERATIONS

Our current implementation is a learning implementation. In production, we should consider:

1. **Manual acknowledgements:** Acknowledge messages only after successful processing.
2. **Dead Letter Queue (DLQ):** Store messages that repeatedly fail processing.
3. **Publisher Confirms:** Verify that RabbitMQ has accepted published messages.
4. **Persistent messages:** Configure messages to survive broker restarts along with durable queues.
5. **Connection recovery:** Handle RabbitMQ disconnections and reconnect appropriately.
6. **Transactional Outbox Pattern:** Prevent inconsistencies when a database update succeeds but publishing the RabbitMQ event fails.
7. **Idempotent consumers:** Handle duplicate message delivery safely.

### Durable Queue vs Persistent Message

These are two different concepts:

- Durable Queue: The queue definition survives a RabbitMQ restart.
- Persistent Message: The message is marked for persistence so RabbitMQ can retain it across restarts.

Using a durable queue alone does not automatically make every message persistent.
