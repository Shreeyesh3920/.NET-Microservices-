# Ocelot API Gateway Implementation in .NET

Ocelot is a .NET API Gateway library that provides a single entry point for routing client requests to multiple microservices.

## Step 1. Create API Gateway project

Create a new ASP.NET Core Web API or Empty project.

```
dotnet new web -n APIGateway
```

## Step 2. Install Ocelot NuGet package

```
dotnet add package Ocelot
```

## Step 3. Create `ocelot.json`

Create `ocelot.json` in the API Gateway project's root directory.

This file contains routing configurations.

Example:

```
{
  "GlobalConfiguration": {
    "BaseUrl": "http://localhost:5188"
  },
  "Routes": [
    {
      "UpstreamHttpMethod": [ "GET" ],
      "UpstreamPathTemplate": "/products",
      "DownstreamPathTemplate": "/api/products",
      "DownstreamScheme": "https",
      "DownstreamHostAndPorts": [
        {
          "Host": "localhost",
          "Port": 7121
        }
      ]
    }
  ]
}
```

### Understanding the configuration

| Property               | Explanation                                                            |
| ---------------------- | ---------------------------------------------------------------------- |
| GlobalConfiguration    | Contains global gateway settings.                                      |
| BaseUrl                | Base URL of the API Gateway.                                           |
| Routes                 | Defines routing rules.                                                 |
| UpstreamHttpMethod     | HTTP methods accepted by the gateway (GET, POST, PUT, DELETE).         |
| UpstreamPathTemplate   | Endpoint exposed by the API Gateway to clients.                        |
| DownstreamPathTemplate | Actual endpoint of the backend microservice.                           |
| DownstreamScheme       | Protocol used to communicate with the downstream service (HTTP/HTTPS). |
| DownstreamHostAndPorts | Hostname and port where the microservice is running.                   |

Example request mapping:

```
Client Request:
http://localhost:5188/products

         |
         v

API Gateway (Ocelot)

         |
         v

Downstream Request:
https://localhost:7121/api/products
```

## Step 4. Configure Program.cs

Register Ocelot services and add Ocelot middleware.

```
using Ocelot.DependencyInjection;
using Ocelot.Middleware;

var builder = WebApplication.CreateBuilder(args);

// Load Ocelot configuration
builder.Configuration.AddJsonFile(
    "ocelot.json",
    optional: false,
    reloadOnChange: true);

// Register Ocelot services in DI
builder.Services.AddOcelot(builder.Configuration);

var app = builder.Build();

// Add Ocelot middleware
await app.UseOcelot();

await app.RunAsync();
```

### Understanding the code

| Code            | Explanation                                                                             |
| --------------- | --------------------------------------------------------------------------------------- |
| `AddJsonFile()` | Loads Ocelot routing configuration.                                                     |
| `AddOcelot()`   | Registers Ocelot services in the DI container.                                          |
| `UseOcelot()`   | Adds Ocelot middleware to the request pipeline to handle and forward incoming requests. |
| `RunAsync()`    | Starts the application.                                                                 |

## Step 5. Run and test

Start your Product Service:

```
dotnet run
```

Start API Gateway on port 5188:

```
dotnet run --urls http://localhost:5188
```

Now test using Postman:

GET

API Gateway endpoint

`http://localhost:5188/products`

Ocelot forwards the request to:

```
GET https://localhost:7121/api/products
```

The Product Service processes the request and returns the response through the API Gateway.

## Step 6. Configure Ocelot for Docker

When running inside Docker, update the downstream configuration:

```
"DownstreamScheme": "http",
"DownstreamHostAndPorts": [
  {
    "Host": "product-service",
    "Port": 8080
  }
]
```

Why the changes?

- `localhost` → `product-service`: Docker service name is used for container-to-container communication.
- `https` → `http`: Uses the Product Service's internal HTTP endpoint.
- `8080`: Internal container port.

Then:

1. Create a Dockerfile for API Gateway.
2. Add API Gateway to `docker-compose.yml`.
3. Attach it to the same Docker network as your microservices.
4. Expose the gateway port to the host.
5. Run:

```
docker compose up -d --build
```

Test:

```
GET http://localhost:5188/products
```

## Quick revision

Ocelot implementation flow

1. Create ASP.NET Core API Gateway project.
2. Install Ocelot NuGet package.
3. Create `ocelot.json` and configure routes.
4. Register Ocelot using `AddOcelot()`.
5. Add Ocelot middleware using `UseOcelot()`.
6. Run and test through the Gateway.
7. For Docker, update downstream URLs to Docker service names and configure Docker networking.

Remember these three things:

- Upstream = Client-facing API endpoint.
- Downstream = Actual microservice endpoint.
- Ocelot = Receives client requests and forwards them to the appropriate microservice.
