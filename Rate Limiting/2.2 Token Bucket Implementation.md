Bro, in C# we can implement Token Bucket Rate Limiting using the built-in System.Threading.RateLimiting namespace.

You don't need to implement token generation, consumption and refill manually. .NET already provides a TokenBucketRateLimiter implementation.

Let's implement it in your ASP.NET Core Web API.
1. Configure Token Bucket in Program.cs
First, add this namespace:
using System.Threading.RateLimiting;


Now configure the rate limiter:

using System.Threading.RateLimiting;

var builder = WebApplication.CreateBuilder(args);

builder.Services.AddControllers();

// Configure Token Bucket Rate Limiting
builder.Services.AddRateLimiter(options =>
{
    options.AddTokenBucketLimiter("TokenBucketPolicy", limiterOptions =>
    {
        limiterOptions.TokenLimit = 5;
        limiterOptions.ReplenishmentPeriod = TimeSpan.FromSeconds(10);
        limiterOptions.TokensPerPeriod = 1;
        limiterOptions.AutoReplenishment = true;
        limiterOptions.QueueLimit = 0;
    });

    options.RejectionStatusCode = StatusCodes.Status429TooManyRequests;
});

var app = builder.Build();

app.UseRouting();

// Enable Rate Limiting middleware
app.UseRateLimiter();

app.MapControllers();

app.Run();



2. Understand the configuration
This is the most important part.
Property	Value	Meaning
TokenLimit	5	Maximum bucket capacity is 5 tokens.
ReplenishmentPeriod	10 seconds	Refill happens every 10 seconds.
TokensPerPeriod	1	One token is added per refill.
AutoReplenishment	true	.NET automatically replenishes tokens.
QueueLimit	0	Requests without available tokens are not queued.
RejectionStatusCode	429	Returns Too Many Requests.

Notice:
limiterOptions.TokenLimit = 5;


This means the bucket can hold a maximum of 5 tokens.
limiterOptions.TokensPerPeriod = 1;


This means .NET adds one token every 10 seconds.
limiterOptions.QueueLimit = 0;


This means if the bucket is empty, reject the request immediately.
3. Apply the Token Bucket policy
One important thing: Registering a policy doesn't automatically apply it to your APIs.

We need to attach the policy to an endpoint.

For example, if you want to apply it to all Product Controller endpoints:
app.MapControllers()
   .RequireRateLimiting("TokenBucketPolicy");


So replace:
app.MapControllers();


with the above code.

Now your complete request pipeline is:
Incoming Request
       |
       v
    Routing
       |
       v
Rate Limiting Middleware
       |
       v
  Token Bucket
       |
       v
  Token Available?
     /       \
   Yes        No
    |          |
    v          v
Controller   HTTP 429


4. Complete Program.cs
Here is the complete implementation:

using System.Threading.RateLimiting;

var builder = WebApplication.CreateBuilder(args);

builder.Services.AddControllers();

builder.Services.AddRateLimiter(options =>
{
    options.AddTokenBucketLimiter("TokenBucketPolicy", limiterOptions =>
    {
        limiterOptions.TokenLimit = 5;
        limiterOptions.ReplenishmentPeriod = TimeSpan.FromSeconds(10);
        limiterOptions.TokensPerPeriod = 1;
        limiterOptions.AutoReplenishment = true;
        limiterOptions.QueueLimit = 0;
    });

    options.RejectionStatusCode = StatusCodes.Status429TooManyRequests;
});

var app = builder.Build();

app.UseRouting();

app.UseRateLimiter();

app.MapControllers()
   .RequireRateLimiting("TokenBucketPolicy");

app.Run();

Start your application and send:

Let's test with our configuration:
- Bucket capacity = 5.
- Refill = 1 token every 10 seconds.
- Queue = 0.

1	4	Allowed
2	3	Allowed
3	2	Allowed
4	1	Allowed

After 10 seconds, one token is replenished and another request can be accepted.
6. Apply rate limiting to a specific endpoint only
Suppose you don't want to apply rate limiting to every controller.

You can use the [EnableRateLimiting] attribute:
using Microsoft.AspNetCore.RateLimiting;

[ApiController]
[Route("api/products")]
[EnableRateLimiting("TokenBucketPolicy")]
public class ProductsController : ControllerBase
{
    // Your endpoints
}


Now only endpoints in this controller use the Token Bucket policy.
7. Important things to remember
1. TokenLimit = Maximum bucket capacity.
2. TokensPerPeriod = Number of tokens replenished each period.
3. ReplenishmentPeriod = Time interval between replenishments.
4. QueueLimit = 0 = Reject immediately when no tokens are available.
5. UseRateLimiter() = Enables rate-limiting middleware.
6. RequireRateLimiting() = Applies the registered policy to endpoints.
One important production consideration: This configuration creates a shared bucket within this application instance. It doesn't automatically create separate limits per user or IP, and multiple application instances have independent buckets. For distributed rate limiting, you need a shared coordination mechanism or distributed rate-limiting solution.


My recommendation: First implement this in your Product Service and test the 429 response. After that, we can implement per-client Token Bucket rate limiting, which is particularly useful in microservices and API Gateway architectures.
