## 2.2 Implementing Token Bucket in ASP.NET Core

.NET provides a built-in implementation of Token Bucket using the `System.Threading.RateLimiting` namespace.

We don't need to implement token generation, consumption, and replenishment manually.

### Step 1: Configure Token Bucket in Program.cs

```
using System.Threading.RateLimiting;

var builder = WebApplication.CreateBuilder(args);

builder.Services.AddControllers();

// Configure Token Bucket Rate Limiting
builder.Services.AddRateLimiter(options =>
{
    options.AddTokenBucketLimiter("TokenBucketPolicy", limiterOptions =>
    {
        limiterOptions.TokenLimit = 5;
        limiterOptions.ReplenishmentPeriod = TimeSpan.FromSeconds(10);
        limiterOptions.TokensPerPeriod = 1;
        limiterOptions.AutoReplenishment = true;
        limiterOptions.QueueLimit = 0;
    });

    options.RejectionStatusCode = StatusCodes.Status429TooManyRequests;
});

var app = builder.Build();

app.UseRouting();

// Enable Rate Limiting Middleware
app.UseRateLimiter();

app.MapControllers()
   .RequireRateLimiting("TokenBucketPolicy");

app.Run();
```

### Step 2: Understand the Configuration

| Property            | Value      | Explanation                                                |
| ------------------- | ---------- | ---------------------------------------------------------- |
| TokenLimit          | 5          | Maximum number of tokens the bucket can hold.              |
| ReplenishmentPeriod | 10 seconds | Time interval between token replenishments.                |
| TokensPerPeriod     | 1          | Number of tokens added during each replenishment.          |
| AutoReplenishment   | true       | Automatically replenishes tokens.                          |
| QueueLimit          | 0          | Rejects requests immediately when no tokens are available. |
| RejectionStatusCode | 429        | HTTP status code returned when the rate limit is exceeded. |

### Step 3: Apply Rate Limiting Policy

Registering a rate-limiting policy does not automatically apply it to endpoints.

We must attach the policy using:

```
app.MapControllers()
   .RequireRateLimiting("TokenBucketPolicy");
```

This applies the Token Bucket policy to all controller endpoints.

Alternatively, apply it to a specific controller using:

```
using Microsoft.AspNetCore.RateLimiting;

[ApiController]
[Route("api/products")]
[EnableRateLimiting("TokenBucketPolicy")]
public class ProductsController : ControllerBase
{
    // API endpoints
}
```

## 3. How Token Bucket Works with This Configuration

Consider the following configuration:

- Bucket Capacity = 5 tokens.
- Refill Rate = 1 token every 10 seconds.
- Each request consumes 1 token.
- Queue Limit = 0.

### Step 1: Initial State

Initially, the bucket contains 5 tokens.

```
       TOKEN BUCKET

      ┌───────────────┐
      │  ●  ●  ●  ●  ●│
      └───────────────┘

      Available: 5 tokens
```

### Step 2: Incoming Requests

Each request consumes one token.

```
Request 1 → Consume 1 token → ALLOWED
Request 2 → Consume 1 token → ALLOWED
Request 3 → Consume 1 token → ALLOWED
Request 4 → Consume 1 token → ALLOWED
Request 5 → Consume 1 token → ALLOWED
```

After five requests:

```
      ┌───────────────┐
      │  ○  ○  ○  ○  ○│
      └───────────────┘

      Available: 0 tokens
```

### Step 3: Another Request Arrives

A sixth request arrives.

- Available token? NO.
- Request is rejected.
- HTTP 429 Too Many Requests is returned.

```
Client
   |
   | Request 6
   v
Token Bucket
   |
   v
No tokens available
   |
   v
HTTP 429
```

### Step 4: Token Replenishment

After 10 seconds, .NET automatically adds one token.

```
       BEFORE REFILL

      ┌───────────────┐
      │  ○  ○  ○  ○  ○│
      └───────────────┘

       AFTER REFILL

          +1 TOKEN
             |
             v

      ┌───────────────┐
      │  ●  ○  ○  ○  ○│
      └───────────────┘

      Available: 1 token
```

Now another request can be accepted.

### Step 5: What if the Bucket Is Already Full?

Suppose the bucket already contains 5 tokens and another replenishment occurs.

The bucket cannot exceed its maximum capacity.

```
Bucket Capacity = 5

Current Tokens = 5

New Token = +1

Final Available Tokens = 5
```

The extra token is discarded.

## 6. Advantages of Token Bucket

1. Supports burst traffic.
2. Controls the average request rate.
3. Protects APIs from excessive incoming traffic.
4. Allows flexible token capacity and replenishment rates.

## 7. Important Things to Remember

| Concept             | Meaning                                                                |
| ------------------- | ---------------------------------------------------------------------- |
| TokenLimit          | Maximum bucket capacity.                                               |
| TokensPerPeriod     | Number of tokens added per replenishment.                              |
| ReplenishmentPeriod | Time interval between replenishments.                                  |
| Token Consumption   | Each request consumes a token.                                         |
| Burst Traffic       | Multiple requests can be accepted immediately if tokens are available. |
| HTTP 429            | Too Many Requests response.                                            |

**Important:** The default configuration creates a limiter shared by requests using that policy within one application instance. It does not automatically provide separate limits per user or IP address. Multiple application instances also maintain independent limiter states unless distributed coordination is implemented.

## 8. Interview-Ready Definition

Token Bucket is a rate-limiting algorithm in which tokens are generated at a configured rate and stored in a bucket with a fixed maximum capacity. Every incoming request consumes a token. If a token is available, the request is allowed; otherwise, it is rejected or queued. It allows controlled burst traffic while maintaining an average request rate.

**Quick Revision:**

- TokenLimit = Maximum bucket capacity.
- TokensPerPeriod = Number of tokens generated.
- ReplenishmentPeriod = Token refill interval.
- Each request consumes a token.
- No tokens = Request rejected.
- Token Bucket = Controlled Rate + Burst Handling.
