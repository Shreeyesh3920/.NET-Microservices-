# Rate Limiting – .NET Notes

## 1. What is Rate Limiting?

Rate Limiting is a technique used to control how many requests a client can send to an API within a specific time period.

**Example:**

- Allow 100 requests per minute.
- If a client sends the 101st request, reject it.
- Return HTTP `429 Too Many Requests`.

### Why do we need Rate Limiting?

1. Prevent API abuse and spam requests.
2. Protect APIs from excessive traffic.
3. Prevent unnecessary database calls.
4. Protect expensive operations like Forgot Password.
5. Maintain API availability and performance.

## 2. Rate Limiting Algorithms

There are five commonly discussed algorithms.

### A. Fixed Window Counter

- Maintains a request counter.
- Counter increases with every request.
- Counter resets after a fixed time period.

**Example:** 5 requests per 10 minutes.

```
10:00 AM → Counter starts at 0

Request 1 → Counter = 1
Request 2 → Counter = 2
Request 3 → Counter = 3
Request 4 → Counter = 4
Request 5 → Counter = 5
Request 6 → REJECTED

10:10 AM → Counter resets to 0
```

**Limitation:** Can allow a burst of requests around the window boundary.

### B. Sliding Window Log

- Stores the timestamp of every request.
- Removes timestamps older than the allowed time window.
- Counts the remaining requests.
- Rejects if the limit is reached.

**Example:** Maximum 5 requests in the last 10 minutes.

### C. Sliding Window Counter

- An improved approach over Fixed Window.
- Uses the current and previous window counters.
- Calculates an approximate request count based on how much of the previous window overlaps the current rolling period.

### D. Token Bucket

- Maintains a bucket containing tokens.
- Each request consumes one token.
- Tokens are replenished over time.
- If no tokens are available, reject the request.

**Example:**

```
Bucket Capacity = 5
Initial Tokens = 5
Refill = 1 token every 2 minutes

Request 1 → 4 tokens
Request 2 → 3 tokens
Request 3 → 2 tokens

After 2 minutes → 3 tokens
```

**Advantage:** Allows controlled bursts while replenishing tokens gradually.

### E. Leaky Bucket

- Incoming requests enter a queue.
- Requests are processed at a fixed rate.
- If the queue is full, reject new requests.

**Purpose:** Smooth out sudden traffic spikes.

## 3. Rate Limiting vs Concurrency Limiting

These are different concepts.

| Rate Limiting                                | Concurrency Limiting                         |
| -------------------------------------------- | -------------------------------------------- |
| Controls requests over time                  | Controls simultaneous requests               |
| Example: 100 requests/minute                 | Example: 10 active requests                  |
| Protects against excessive request frequency | Protects against too many ongoing operations |

## 4. How to implement Rate Limiting in .NET?

.NET provides built-in Rate Limiting middleware through:

```
using System.Threading.RateLimiting;
```

Example using Token Bucket:

```
builder.Services.AddRateLimiter(options =>
{
    options.AddTokenBucketLimiter("TokenBucket", limiter =>
    {
        limiter.TokenLimit = 5;
        limiter.TokensPerPeriod = 1;
        limiter.ReplenishmentPeriod = TimeSpan.FromSeconds(10);
        limiter.AutoReplenishment = true;
        limiter.QueueLimit = 0;
    });

    options.RejectionStatusCode = 429;
});
```

Register middleware:

```
app.UseRateLimiter();
```

Apply the policy:

```
[EnableRateLimiting("TokenBucket")]
[HttpGet("products")]
public IActionResult GetProducts()
{
    return Ok();
}
```

**Important:** Registering a policy doesn't automatically apply it. Attach it to an endpoint or controller.

## 5. Global vs Partitioned Rate Limiting

### Global Rate Limiting

All requests share the same rate limit.

Example:

- Maximum 100 requests per minute for the entire application.

### Partitioned Rate Limiting

Each client gets an independent rate limit.

A partition can be created using:

- IP address
- User ID
- API key
- Email address

Example:

```
IP A → Own rate limit
IP B → Own rate limit
IP C → Own rate limit
```

In .NET, `RateLimitPartition` is used to create separate limiters for different keys.

## 6. Forgot Password – Real-World Example

**Requirement:**

- Maximum 5 requests per IP in 10 minutes.
- Maximum 5 requests per email in 10 minutes.

Why check both?

- IP checking prevents one IP from spamming different email addresses.
- Email checking prevents multiple IPs from targeting the same email address.

### Suggested implementation

```
ForgotPassword API
       |
       v
Custom Action Filter
       |
       v
Rate Limiter
       |
       +---- Check IP Counter
       |
       +---- Check Email Counter
       |
       v
Both Allowed?
       |
       +---- No → HTTP 429
       |
       +---- Yes → Forgot Password Logic
```

Use Fixed Window counters for this requirement.

### Where do we store counters?

| Application deployment         | Storage   |
| ------------------------------ | --------- |
| Single application instance    | In-memory |
| Multiple application instances | Redis     |

Redis provides shared counters across multiple application instances.

For Redis, use atomic operations (such as Lua scripting) when checking and updating both counters together.

## 7. Important Interview Questions

**Q1. What is Rate Limiting?**

Controlling the number of requests a client can make within a specified time period.

**Q2. Which algorithm allows bursts?**

Token Bucket.

**Q3. Difference between Fixed Window and Token Bucket?**

Fixed Window uses a request counter that resets after a fixed period. Token Bucket uses tokens that replenish over time.

**Q4. Why use Redis for Rate Limiting?**

To maintain shared counters across multiple application instances.

**Q5. Is Redis mandatory in microservices?**

No. It is useful when multiple instances need to share the same rate-limit state.

**Q6. What HTTP status code is returned when the limit is exceeded?**

HTTP 429 – Too Many Requests.

**Q7. Is Concurrency Limiting the same as Rate Limiting?**

No. Rate Limiting controls request frequency; Concurrency Limiting controls simultaneous operations.
